# E2E 测试专用数据库 PRD

## 问题陈述

当前 e2e 测试存在以下问题：

1. **数据管理不一致**：测试数据与生产数据混合，容易产生遗留数据
2. **应用生命周期频繁切换**：部分测试文件中存在多次启动/关闭应用的情况，增加测试时间
3. **测试数据状态耦合**：后续测试可能依赖前面测试创建的数据，当前置测试失败时会连带影响后续测试

## 解决方案

使用**测试专用数据库**实现测试环境隔离：

- 支持并行测试, 比如 4 workers
- 每个测试 worker 使用独立的临时数据目录
- 应用在测试 worker 级别只启动和关闭一次
- 测试文件之间数据隔离，避免互相影响
- 测试完成后自动删除临时数据目录

## 用户故事

- 作为测试工程师，我希望每个测试 worker 使用独立的数据目录，以便测试之间互不干扰
- 作为测试工程师，我希望应用在 worker 级别只启动一次，以便减少测试执行时间
- 作为测试工程师，我希望测试完成后自动清理数据，以便避免手动清理的遗漏

## 功能清单

### 功能-测试数据库隔离

- 每个 worker 使用独立的临时数据目录（位于系统临时目录）
- 测试数据目录与应用默认数据目录完全隔离
- 测试完成后自动删除临时数据目录
- 测试数据使用唯一标识（e2e_ 前缀）避免与生产数据混淆

### 功能-应用生命周期管理

- 应用在测试 worker 生命周期内只启动和关闭一次
- 测试执行期间应用保持运行状态
- 测试之间不会反复重启应用

### 功能-测试数据管理

- 测试开始前自动准备共享的基础测试数据
- 不涉及数据操作的测试项复用共享数据
- 新建类测试直接测试新建功能，不依赖预置数据
- 删除类测试自行准备足够数据，不影响共享数据

### 功能-测试数据可见性

- 测试数据创建后界面自动更新显示
- 测试数据使用唯一标识便于识别

### 功能-视图切换清洁

- 视图切换时自动清理可能残留的模态框
- 避免因状态残留导致的测试失败

## 行为约束矩阵

| 场景 | 触发条件 | 前置状态 | 预期行为 | 预期结果状态 |
|------|----------|----------|----------|-------------|
| Worker 启动 | 测试 runner 初始化 worker | 无 | 创建临时数据目录并启动应用 | 应用使用临时数据目录运行 |
| 测试初始化 | 测试文件的第一个测试开始前 | 应用已启动 | 创建基础测试数据并更新界面 | 界面显示测试数据 |
| 测试项执行 | 各个测试函数执行 | 数据已创建 | 测试执行 | 测试通过或失败 |
| Worker 结束 | 所有测试项完成 | 无 | 关闭应用并删除临时数据目录 | 应用关闭，数据清理完成 |

## 状态流转

```
创建临时目录 → 启动应用 → 创建测试数据 → 测试项执行 → 关闭应用 → 删除临时目录
```

## 超出范围

- 测试执行器层面的并行配置
- 单个测试项内部的初始化/清理逻辑
- 测试数据的持久化（每次运行都是新数据）

## 约束检查清单

- [ ] 每个 worker 只有一个应用生命周期（启动/关闭）
- [ ] 每个 worker 使用独立的临时数据目录
- [ ] 测试开始前自动创建基础测试数据
- [ ] 创建数据后界面自动刷新显示
- [ ] 新建类测试不依赖预置数据
- [ ] 删除类测试自行准备足够数据
- [ ] 后续测试不依赖可能被修改的共享数据
- [ ] 测试数据使用唯一标识区分

## PRD 进一步说明

- 成功标准：独立临时目录、单次应用生命周期、自动清理、数据隔离、无状态耦合
- 约束：支持并行测试、临时目录位于系统临时目录、测试数据与生产数据完全隔离
