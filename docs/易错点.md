# 易错点

本文档记录项目开发和测试过程中发现的常见易错点，以便查阅和避免重复踩坑。

## E2E 测试

### 缓存相关

#### PyTagGroups 缓存导致标签不显示

**问题描述**：通过 API 创建的标签不会立即出现在自动完成下拉列表中。

**根本原因**：`PyTagGroups.getTags()` 使用缓存机制，新创建的标签需要清除缓存后才能被读取。

**代码路径**：

- `src/services/PyTagGroups.ts` - `getTags()` 方法
- `src/services/TagService.ts` - `search()` 方法调用 `pyTagGroups.search()`

**解决方案**：

```typescript
// 创建标签后清除缓存
await electronTest.createImageTags(3, 'test_prefix');
await electronTest.clearTagCache('image');  // 必须调用
```

**影响范围**：

- 标签自动完成测试
- 标签筛选测试
- 任何依赖实时标签列表的功能测试

### Playwright 操作

#### `fill()` vs `pressSequentially()` 的区别

**问题描述**：Playwright 提供了多种输入方式，需要了解它们的差异以选择合适的方案。

**验证结果**（通过 `e2e/test-fill-vs-press.spec.ts` 测试验证）：

- `fill()`：直接设置输入框的值，**会触发 input 事件**，自动完成功能正常工作
- `pressSequentially()`：模拟键盘逐字输入，**会触发 input 和 keyup 事件**

**差异对比**：

| 特性 | `fill()` | `pressSequentially()` |
|------|----------|----------------------|
| 执行速度 | 快（直接设置值） | 慢（逐字输入，可配置 delay） |
| 触发事件 | input | input + keyup |
| 适用场景 | 快速填充表单 | 需要模拟真实打字场景 |

**代码示例**：

```typescript
// 快速填充，不关心打字过程
await page.fill('#tagInput', 'test');

// 模拟真实打字，逐字输入
await page.locator('#tagInput').pressSequentially('test', { delay: 50 });
```

**注意**：`page.type()` 在 Playwright v1.38.0+ 中已弃用，请使用 `locator.pressSequentially()` 替代

### 测试生命周期

#### Electron 单实例应用的测试模式

**问题描述**：使用 `beforeEach` 启动应用时报错 "Another instance is already running"。

**根本原因**：Electron 应用是单实例模式，不能在每个测试用例前都启动新实例。

**解决方案**：

```typescript
// ❌ 错误
import { test } from '@playwright/test';
test.beforeEach(async () => {
  await electronApp.launch();
});

// ✅ 正确
test.beforeAll(async () => {
  await electronTest.launch();
});

test.afterAll(async () => {
  await electronTest.close();
});

// 每轮测试后重置状态
test.afterEach(async () => {
  await electronTest.cleanupAndReset();
});
```

### UI 状态管理

#### 测试间状态隔离

**问题描述**：前一个测试打开的模态框影响后一个测试，导致测试失败。

**解决方案**：使用 `cleanupAndReset()` 在每轮测试后清理状态：

```typescript
test.afterEach(async () => {
  await electronTest.cleanupAndReset();
});
```

`cleanupAndReset()` 会执行：

1. 清理所有 `e2e_` 前缀的测试标签
2. 关闭所有模态框（图片详情、提示词详情、标签管理器等）
3. 回到图像主界面

## 标签系统

### 数据一致性

#### API 创建标签后需要刷新缓存

**问题描述**：使用 `addImageTags` API 创建标签后，前端界面不显示新标签。

**根本原因**：`addImageTags` 直接操作数据库，不会触发缓存清除。

**解决方案**：

```typescript
// 创建标签
await page.evaluate(() => window.electronAPI.addImageTags(...));

// 清除缓存
await electronTest.clearTagCache('image');

// 刷新标签筛选区
await electronTest.refreshTagFilters();
```

## 代码规范

### 导入规范

#### 同目录 vs 跨目录导入

**规则**：

- **同目录模块**：直接导入具体文件，不通过 index
- **跨目录导入**：统一使用 index

**示例**：

```typescript
// 同目录 - 直接导入具体文件
import { helper } from './helper.ts';

// 跨目录 - 使用 index
import { utils } from '../utils';
```

### 字符串处理

#### 字符串截取使用 `slice()`

**规范**：项目中统一使用 `slice()` 进行字符串截取，不使用 `substring()`。

**示例**：

```typescript
// ✅ 正确
const prefix = str.slice(0, 10);

// ❌ 避免使用
const prefix = str.substring(0, 10);
```

## ID 比较

### 使用 `isSameId()` 进行 ID 比较

**问题描述**：ID 可能是字符串或数字类型，直接使用 `===` 比较可能失败。

**解决方案**：

```typescript
// ❌ 可能失败
if (id1 === id2) { ... }

// ✅ 正确
if (this.app.isSameId(id1, id2)) { ... }
```

## 缓存完整性

### 缓存中的提示词对象可能缺少 `images` 字段

**问题描述**：从图像详情点击"编辑提示词"跳转到提示词详情后，参考图像区域为空（图像主页下拉较深时必现）。

**根本原因**：`ImageDetailManager.collectPromptRefs` 在提示词 LRU 缓存未命中时，会用 `image.promptRefs` 现拼一个**没有 `images` 字段的最小 `IPrompt` 并写回缓存**；`PromptDetailManager.loadImages` 只遍历 `prompt.images`，字段缺失即渲染空白。启动时提示词缓存只有第一页 100 条（pageSize=100），深位置的图像关联的旧提示词大概率不在缓存中，故下拉越深越易复现。

**解决方案**：

```typescript
// 读取端做完整性守卫（区分"字段缺失"与"空数组"，数据库路径始终返回 images 数组）
if (!Array.isArray(latestPrompt.images)) {
  const fullPrompt = await window.electronAPI.getPromptById(latestPrompt.id);
  if (fullPrompt) {
    cacheManager.cachePrompt(fullPrompt);
    latestPrompt = fullPrompt;
  }
}
```

**通用教训**：跨模块传递的缓存对象不能假设字段完整（`IPrompt.images?` 是可选的）；从局部数据拼装的对象回写共享缓存前，要么补全关键字段，要么读取端按"字段缺失 = 数据不完整"兜底拉取全量。

## SQLite

### `GROUP_CONCAT(DISTINCT x, sep)` 是非法语法

**问题描述**：标签序列化改用自定义分隔符后（`GROUP_CONCAT(DISTINCT pt.name, char(31))`），应用启动即失败：`SQLITE_ERROR: DISTINCT aggregates must have exactly one argument`。

**根本原因**：SQLite 规定聚合函数带 `DISTINCT` 时**只允许一个参数**，不能同时指定分隔符。该错误是运行时错误，tsc/oxlint 完全无法发现。

**解决方案**（二选一）：

```sql
-- 1. 关联表有复合主键 (prompt_id, tag_id) 保证 JOIN 结果天然去重时，直接去掉 DISTINCT
GROUP_CONCAT(pt.name, char(31))

-- 2. 确实需要去重 + 自定义分隔符时，用派生表先去重
(SELECT GROUP_CONCAT(name, char(31)) FROM (SELECT DISTINCT pt.name FROM ...) t)
```

**通用教训**：本项目驱动为 sqlite3（回调式），任何 SQL 文本改动都不在 pnpm check 覆盖范围内；改完必须启动应用冒烟验证首屏查询路径（get-prompts-paginated / get-images-paginated 是启动必经路径）。

## 自动完成组件

### 失焦延迟隐藏必须带焦点复核

**问题描述**：e2e 键盘导航用例间歇性失败——下拉框偶发未出现，或回车后提交的是输入框前缀原文而非选中项。真人操作几乎不触发。

**根本原因**：`blurHandler` 用 `setTimeout(() => hideDropdown(), 200)` 延迟隐藏（为点击建议项留时间窗）。该定时器一旦埋下便不可撤销：若 200ms 内重新聚焦并继续交互，过期定时器会在导航中途摘掉下拉框的 `active`，回车时组件认为"无下拉"，把输入框原文当标签提交。

**解决方案**：

```typescript
this.blurHandler = () => {
  clearTimeout(this.blurHideTimer);
  this.blurHideTimer = setTimeout(() => {
    if (document.activeElement !== this.input) {  // 焦点复核
      this.hideDropdown();
    }
  }, 200);
};
// focus / handleInput 入口处 clearTimeout 撤销未到期定时器；destroy 一并清理
```

**通用教训**：`setTimeout` 式延迟隐藏是"定时炸弹"模式——任何依赖中间状态（高亮、展开态）的后续操作都可能被过期回调破坏；延迟回调执行时必须重新验证前提条件仍成立。
