# 易错点

本文档记录项目开发和测试过程中发现的常见易错点，以便查阅和避免重复踩坑。

## E2E 测试

### 缓存相关

#### PyTagGroups 缓存导致标签不显示

**问题描述**：通过 API 创建的标签不会立即出现在自动完成下拉列表中。

**根本原因**：`PyTagGroups.getTags()` 使用缓存机制，新创建的标签需要清除缓存后才能被读取。

**代码路径**：

- `src/services/PyTagGroups.ts` - `getTags()` 方法
- `src/services/TagService.ts` - `search()` 方法调用 `pyTagGroups.search()`

**解决方案**：

```typescript
// 创建标签后清除缓存
await electronTest.createImageTags(3, 'test_prefix');
await electronTest.clearTagCache('image');  // 必须调用
```

**影响范围**：

- 标签自动完成测试
- 标签筛选测试
- 任何依赖实时标签列表的功能测试

### Playwright 操作

#### `fill()` vs `pressSequentially()` 的区别

**问题描述**：Playwright 提供了多种输入方式，需要了解它们的差异以选择合适的方案。

**验证结果**（通过 `e2e/test-fill-vs-press.spec.ts` 测试验证）：

- `fill()`：直接设置输入框的值，**会触发 input 事件**，自动完成功能正常工作
- `pressSequentially()`：模拟键盘逐字输入，**会触发 input 和 keyup 事件**

**差异对比**：

| 特性 | `fill()` | `pressSequentially()` |
|------|----------|----------------------|
| 执行速度 | 快（直接设置值） | 慢（逐字输入，可配置 delay） |
| 触发事件 | input | input + keyup |
| 适用场景 | 快速填充表单 | 需要模拟真实打字场景 |

**代码示例**：

```typescript
// 快速填充，不关心打字过程
await page.fill('#tagInput', 'test');

// 模拟真实打字，逐字输入
await page.locator('#tagInput').pressSequentially('test', { delay: 50 });
```

**注意**：`page.type()` 在 Playwright v1.38.0+ 中已弃用，请使用 `locator.pressSequentially()` 替代

### 测试生命周期

#### Electron 单实例应用的测试模式

**问题描述**：使用 `beforeEach` 启动应用时报错 "Another instance is already running"。

**根本原因**：Electron 应用是单实例模式，不能在每个测试用例前都启动新实例。

**解决方案**：

```typescript
// ❌ 错误
import { test } from '@playwright/test';
test.beforeEach(async () => {
  await electronApp.launch();
});

// ✅ 正确
test.beforeAll(async () => {
  await electronTest.launch();
});

test.afterAll(async () => {
  await electronTest.close();
});

// 每轮测试后重置状态
test.afterEach(async () => {
  await electronTest.cleanupAndReset();
});
```

### UI 状态管理

#### 测试间状态隔离

**问题描述**：前一个测试打开的模态框影响后一个测试，导致测试失败。

**解决方案**：使用 `cleanupAndReset()` 在每轮测试后清理状态：

```typescript
test.afterEach(async () => {
  await electronTest.cleanupAndReset();
});
```

`cleanupAndReset()` 会执行：

1. 清理所有 `e2e_` 前缀的测试标签
2. 关闭所有模态框（图片详情、提示词详情、标签管理器等）
3. 回到图像主界面

## 标签系统

### 数据一致性

#### API 创建标签后需要刷新缓存

**问题描述**：使用 `addImageTags` API 创建标签后，前端界面不显示新标签。

**根本原因**：`addImageTags` 直接操作数据库，不会触发缓存清除。

**解决方案**：

```typescript
// 创建标签
await page.evaluate(() => window.electronAPI.addImageTags(...));

// 清除缓存
await electronTest.clearTagCache('image');

// 刷新标签筛选区
await electronTest.refreshTagFilters();
```

## 调试技巧

### 日志记录

#### E2E 测试调试必须使用日志

**原则**：不要猜测问题原因，必须通过日志定位。

**推荐做法**：

```typescript
// 在关键步骤添加日志
await logDebug(page, '开始创建标签');
await createTag();
await logDebug(page, '标签创建完成');

// 截图记录关键状态
await page.screenshot({ path: 'debug-state.png' });
```

**禁止**：

- 凭猜测修改代码
- 没有日志和截图就下结论
- 反复尝试而不分析根本原因

## 代码规范

### 导入规范

#### 同目录 vs 跨目录导入

**规则**：

- **同目录模块**：直接导入具体文件，不通过 index
- **跨目录导入**：统一使用 index

**示例**：

```typescript
// 同目录 - 直接导入具体文件
import { helper } from './helper.ts';

// 跨目录 - 使用 index
import { utils } from '../utils';
```

---

### 字符串处理

#### 字符串截取使用 `slice()`

**规范**：项目中统一使用 `slice()` 进行字符串截取，不使用 `substring()`。

**示例**：

```typescript
// ✅ 正确
const prefix = str.slice(0, 10);

// ❌ 避免使用
const prefix = str.substring(0, 10);
```

## ID 比较

### 使用 `isSameId()` 进行 ID 比较

**问题描述**：ID 可能是字符串或数字类型，直接使用 `===` 比较可能失败。

**解决方案**：

```typescript
// ❌ 可能失败
if (id1 === id2) { ... }

// ✅ 正确
if (this.app.isSameId(id1, id2)) { ... }
```

## 时区处理

### 使用本地时间格式

**规范**：使用 `src/utils/TimeUtils` 的 `localTime()` 函数处理时间显示。

**示例**：

```typescript
import { localTime } from '../utils/TimeUtils';

// ✅ 正确
const displayTime = localTime(timestamp);

// ❌ 避免直接使用 toLocaleString
const displayTime = new Date(timestamp).toLocaleString();
```
