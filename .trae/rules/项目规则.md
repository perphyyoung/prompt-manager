# Project Rule - AI 开发约束

- 使用中文回答
- 不要过度思考, 问题复杂时, 使用调试日志定位问题
- 添加功能时有更好的想法，先与用户商量

- 修改前确认需求，修改后通过 `npm run build` 验证
- 改代码前，先简述计划与影响范围; 如果有类似的功能已实现, 给出复用代码的利弊分析
- 做出修改后, 禁止直接删除日志代码, 需要我确认才能删除
- 删除时, 一次不要删除超过 100 行, 分次删除; 已删除方法的注释也删除
- 不要保留弃用方法
- 更改代码时, 需要同步更改注释, 不要修改不必要的空格和空行

- 调试时使用 `logger.js` 写入 `debug.log`; 删除日志时, 保留日志系统

- 启动应用、安装依赖时提示用户操作, 而不是启动 `npm start`
- 包管理: 使用 `cnpm` 替代 `npm`

- 网格视图没有多选功能, 只有列表视图和紧凑视图有多选功能

- 新功能通过 TypeScript 实现
- 命名规范: 数据库 `snake_case`，前端 `camelCase`
- 命名体现出变量/函数/类的作用和类型, 避免太泛的通用名称
- 功能相似的代码, 应使用相同的命名规则
- 字符串字面量定义在 Constants 类中
- 新添加的 CSS 类名使用 BEM 命名规范样式
- 统一使用 isSameId.js 的 isSameId() 函数进行 ID 比较，避免类型不匹配
- 注释简洁
- 输出的 Markdown 符合 markdownlint
- 截取字符串时, 使用 slice()
- 同目录模块 之间导入时，直接导入具体文件，不通过 index.js; 跨目录导入 时，统一使用 index.js
- 统一使用 CacheManager 管理缓存
- 时区处理: 统一使用本地时间格式: TimeUtils.js 的 localTime()

- skill.md 中不出现中文, 中文写在 skill-cn.md 中
