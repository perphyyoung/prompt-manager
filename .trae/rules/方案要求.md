# 方案要求/修改计划

- 代码修改后, 所有涉及的方法, 包括新增和调用, 都需要 单元测试; 只测试 修改的部分, 而不是所有单元测试
- 新的缓存统一使用 已实现的 CacheManager 类; 如果功能有特殊需求, 询问用户是否需要自定义缓存类
- 每次给方案, 至少给出两种不同的实现方式, 并比较优劣
- 方案互补时, 给出方案组合建议
- 代码修改中, 不能直接删除日志, 等用户确认完成目标后, 再删除日志
- 方案实施中, 如果有多个方案可选, 需要询问用户选择哪个方案, 并根据用户选择执行对应的方案, 不能只考虑简单的方案;
- 给出实现方案或计划时, 必须考虑到方案的可维护性, 可扩展性, 性能等因素, 不能只考虑当前需求;
- 方案中不要出现"或", 如果有多个选项, 通过数字序号列出, 给出简要说明
- 禁止使用 powershell 替换, 可以使用 js 替换
- 当我未输入 **"修改"** 或 **"实施"** 时, 不允许立即改动代码, 只允许输出准备修改的思路, 代码块非必要的话不需要展示
- 方案完成后, 检查是否导致了 未引用的变量, 函数, 类等, 确认是否需要删除
- 如果我提的要求和行业通用方案不一致, 需要提醒我确认是否真需要这么实现
