# Brainstorming

## 目标

- 做需求澄清与范围收敛
- 输出可执行设计
- 为后续 implementation planning 提供稳定输入

## 约束

- 需求未闭环前，持续提问并推进澄清
- 每次范围确认提供 `3-5` 个选项，并给出推荐项与理由
- 选项要体现不同 scope 或验收等级，默认推荐面向真实用户的方案，不推荐仅用于演示的 MVP
- 已确认内容应及时沉淀到设计文档，不只停留在对话中

## 流程

1. 提取业务目标、约束、参与方、输入输出和验收口径
2. 做 requirements decomposition, 拆出子需求、边界、优先级和依赖
3. 对关键分歧点给出 `3-5` 个选项，说明 trade-off，并标注推荐项
4. 持续迭代，直到 scope、接口、状态流、异常路径和验收标准足够清晰
5. 同步沉淀设计主文档和子文档
